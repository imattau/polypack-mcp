# APT repository maintenance

The release workflow publishes the Debian package to GitHub Pages at:

```text
https://imattau.github.io/polypack-mcp
```

Before the first release, create a dedicated signing key and add these
repository secrets under **Settings → Secrets and variables → Actions**:

- `APT_GPG_PRIVATE_KEY`: ASCII-armored private key exported with
  `gpg --armor --export-secret-keys <key-id>`
- `APT_GPG_KEY_ID`: the key fingerprint (or signing key ID)

Keep the private key dedicated to this repository and do not commit it. A
passphrase-protected key is not currently supported by the non-interactive
release job; use a dedicated key with no passphrase and protect it as an
Actions secret.

Enable GitHub Pages once under **Settings → Pages** by selecting **GitHub
Actions** as the source. Each version tag matching `v*.*.*` then builds and
signs the `stable`/`main` APT repository and deploys it automatically.

To create a suitable key locally:

```sh
gpg --quick-generate-key 'Polypack MCP APT <apt@polypack.dev>' rsa4096 sign 2y
gpg --list-secret-keys --keyid-format LONG
gpg --armor --export-secret-keys <key-id> > polypack-mcp-apt-private.asc
```

The public key is generated by the workflow alongside the repository metadata,
so clients can download `gpg.key` from the same Pages site.
